# Product

## Register

product

## Users

catbuddy serves developers and technical makers who want a capable coding agent on their own computer without giving up control of their projects, provider account, or operating costs. They use it during active development: choosing a workspace, configuring an AI provider, asking for changes, reviewing tool activity, and continuing the same work from another device when needed.

## Product Purpose

catbuddy is a desktop-first AI development partner that runs the agent locally, keeps filesystem authority on the user's machine, and lets the user bring their own model provider. The product succeeds when a new user can install it, connect a provider safely, verify that the connection works, choose a suitable model, and complete a useful coding task without editing environment files or learning catbuddy's internal architecture.

## Brand Personality

Capable, warm, and trustworthy. The product should feel like a technically serious teammate with a light cat-like character: direct when work is in progress, calm when something fails, and personable without becoming distracting or childish.

## Anti-references

- A developer tool that requires editing `.env` or JSON before the first useful action.
- A generic AI dashboard built from indistinguishable cards, blue-purple gradients, decorative glass, and vague claims.
- A playful mascot experience that hides system state, provider cost, errors, or security boundaries.
- A settings screen that accepts secrets without explaining storage, cannot verify credentials, or appears to save changes that are not active.
- A dense control panel that exposes implementation terminology instead of guiding the user's next decision.

## Design Principles

1. **Useful in one guided pass.** First launch should lead from provider choice to a verified first message without documentation detours.
2. **Trust is visible.** Explain where keys live, never echo full secrets, expose connection state, and make destructive credential actions explicit.
3. **Progressive power.** Give common providers and sensible model defaults first; reveal custom endpoints and advanced options only when needed.
4. **State over decoration.** Use visual emphasis for active provider, validation, saving, errors, and agent activity—not ornamental effects.
5. **Local authority stays legible.** Workspace access, desktop execution, and remote-control boundaries must remain understandable at the point of action.

## Accessibility & Inclusion

Target WCAG 2.2 AA for contrast, keyboard navigation, focus visibility, labels, and error association. Support reduced motion, do not rely on color alone for provider or validation states, keep all secret-management flows keyboard accessible, and preserve complete Simplified Chinese and English copy for the primary setup path.
